## Traps

- **Line endings.** Most sources are CRLF on both branches (`effect.cpp`, `renderfunctions.cpp`, …). These are CRLF on main and LF on 2.0.x, so a cherry-pick conflicts on the whole file: `main.cpp`, `engine/cacher.cpp`, `engine/cacher_audio.cpp`, `engine/cacher_video.cpp`, `ui/timelinewidget_paint.cpp`, `ui/timelinewidget_ghosts.cpp`, `ui/blur.{h,cpp}`. Port those by hand or with `git apply --ignore-whitespace -3`, keep the target's endings (check with `file`), never `git clang-format`. Recompute by looping over files common to both trees and comparing `git show origin/main:f | grep -c $'\r$'` with the same on `origin/2.0.x:f`.
- **Nothing was renamed or deleted.** `git diff --find-renames --name-status origin/main origin/2.0.x -- src` is 45 A, 241 M, 0 D/R. "Moved" code means the old file stays, slimmed or turned into a shim, and the new file sits alongside. A 1.x fix always finds its file on 2.0.x, but the code may no longer be in it (see the map).
- **amber-engine boundary is enforced** (since cd86c1b3d). The OBJECT library (`src/CMakeLists.txt` amber-engine block, plus `target_sources` in `src/core/CMakeLists.txt` and `src/engine/CMakeLists.txt`) no longer links `Qt6::Widgets`/`OpenGLWidgets`/`OpenGL` (`Qt6::Svg` is back since Alpha Mask, for `QSvgRenderer`; it pulls Gui only, no widgets): `#include <QWidget>` (or any widget class) in engine code fails to compile, and `amber-test-headless-render` links the engine with no UI sources and no stubs, so a call into `ui/`, `panels/`, `dialogs/` or `global/global.h` fails to link. Gap: `<QtWidgets/QWidget>` still compiles (`/usr/include/qt6` is on the path); only the link catches it. A main fix that, in engine code, opens a `QMessageBox`/`QFileDialog`, touches a panel or `amber::Global`, or uses `QApplication` becomes, on 2.0.x:
  - message / question / file dialog → `amber::app_ctx->showMessage()` / `showQuestion(title, text, warning, default_no)` / `showOpenFileDialog()`; `showMessage` off the GUI thread is queued and returns at once;
  - project state (filename, modified, current sequence, history, recents, autorecovery, rendering state) → `amber::project_io`; the UI refresh hangs off ProjectIO's signals in `AmberGlobal`'s constructor;
  - `QApplication::instance()` / `qApp` → `QCoreApplication::instance()`;
  - folder/sequence icons are produced UI-side (`AppContext::mediaTypeIcon`), footage icons/throbber via `setMediaIcon` / `stopMediaThrobber`.
  A new `AppContext` virtual needs an implementation in `ui/appcontextimpl.cpp` and `core/headlessappcontext.cpp` (test stubs derive from the latter). Export setup is `prepare_export()` / `finish_export()` (`rendering/exportthread.cpp`); ExportDialog keeps only viewer/dialog state.
- **New source file:** engine-side goes into the amber-engine list (or `core/`/`engine/` subdir CMakeLists), UI-side into `UI_SOURCES`. Effects shaders go into `AMBER_EFFECTS` (main: `OLIVE_EFFECTS`).
- **Renames** main → 2.0.x:

- **Alpha Mask: binding 3 has four users.** LUT (`lut_path` file field), curve field, mask (`mask_path` file field), `original="1"`: one per effect, `parseEffectXml()` keeps the first in that order and warns. The mask (`Effect::process_mask()`) decodes on the render thread only when the path changes (`QImageReader` with EXIF auto-transform, or `QSvgRenderer` at 2048 px on the long side, capped at 4096 via `setScaledSize()`, straight-alpha RGBA8; a header claiming > 16384 px a side or > 256 MP is rejected before decoding. `QImageReader::setAllocationLimit()` is static and process-wide (MB, default 256): never set it from the render thread), uploads through `cb->resourceUpdate()` like the curve texture, and is freed in `close()`; no file or a failed decode binds a 1x1 placeholder with `mask_size` (0, 0), which the shader treats as a passthrough. `mask_size` is an automatic uniform written in `Effect::process_shader()` next to `lutSize`. - **PRs:** fetch with `git fetch origin pull/N/head:refs/remotes/pr/N`. Merge on main with `gh pr merge N --squash --subject "..." --body ""` (keeps the author, no trailers), then port to 2.0.x with `git cherry-pick` (author preserved). - **`ComposeSequenceParams::cache` is required when `params.video`** (`compose_audio()` runs without one): `compose_sequence()` returns early with a warning when it's null on the video path. A new render path creates pipelines/buffers through `params.cache`, never with `newGraphicsPipeline`/`newBuffer` per frame; only SRBs go to `transientResources`. Never store a cached pipeline or pooled buffer (eviction, per-frame pool).
- **Drop Shadow is drawn by the compositor, not by the effect chain.** `DropShadowEffect` sets no flags, so `process_effect()` skips it; `render_and_blend_clip()` looks it up in the clip-shader loop (last enabled wins, gated by `shaders_are_enabled`, skipped with `disable_blending`) and `draw_drop_shadow()` runs between `render_clip_to_backbuffer()` and the clip's `rhi_blit_srcover()`, from `back_tex1`'s alpha (the clip as transformed, Corner Pin included). The horizontal blur pass writes into whichever of the clip's own ping-pong textures (`ClipRhiResources::tex[0]`/`[1]`) isn't `textureID`: no texture of its own. Its screen-space Y offset becomes +V on OpenGL and -V on Vulkan/D3D/Metal (`isYUpInFramebuffer()`), tied to the back-buffer pass + srcover flip pair: touching that flip chain means re-running the Vulkan GPU tests. A core shader (`dropshadow.frag`, with `common.vert`) is wired in `qt_add_shaders` (`src/CMakeLists.txt`), a `QShader` in `ComposeSequenceParams`, `RenderThread` (member, `init_rhi_resources()`, the params in `paint()`) and the test harness (`load_core_shaders()`, `render_frame()`).
- **ShaderToy y flip lives in two places, both needed.** The generated `main()` flips `fragCoord` (`(vTexCoord.x, 1 - vTexCoord.y) × iResolution.xy`) and the `amber_texture`/`amber_textureLod`/`amber_texelFetch` helpers flip the `iChannel0` reads (`core/shadertoy.cpp`). Write and read mappings are independent: dropping either one turns a passthrough upside down (pinned by `shadertoyFragCoordIsYUp` and `shadertoyReadsAreIdentity` on GL and Vulkan). Sampling calls the helpers can't flip (`textureGrad*`, `textureGather*`, `texture*Offset`, `textureProj*`) are rejected by the preprocessor.
- **The generated varying must be named `vTexCoord`**, common.vert's output name: the OpenGL backend's GLSL 150 has no location qualifiers and links varyings by name. A renamed input (`amber_TexCoord`) links without error on GL and reads 0 (fragCoord.y = H everywhere); Vulkan matches by location and hides it.
- **`effects` is a `std::deque<EffectMeta>`**, not a QVector: `Effect::meta` and the add-effect menu's `QAction` data hold `EffectMeta*`, and `register_shadertoy_effect()` (import dialog) appends at runtime. Never turn it back into a reallocating container or take `&effects[i]` across a registration with one.
- **`Viewer::scrub_next_render_` is a one-shot flag consumed by `ViewerWidget::request_render`**; any new playhead-moving path that should count as scrubbing (half resolution while scrubbing, settle render) must go through `Viewer::seek()`. A `frame_update()` without a preceding `seek()` is a paused edit and always renders at the preview divider.
