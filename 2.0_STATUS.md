## Traps

- **Line endings.** Most sources are CRLF on both branches (`effect.cpp`, `renderfunctions.cpp`, …). These are CRLF on main and LF on 2.0.x, so a cherry-pick conflicts on the whole file: `main.cpp`, `engine/cacher.cpp`, `engine/cacher_audio.cpp`, `engine/cacher_video.cpp`, `ui/timelinewidget_paint.cpp`, `ui/timelinewidget_ghosts.cpp`, `ui/blur.{h,cpp}`. Port those by hand or with `git apply --ignore-whitespace -3`, keep the target's endings (check with `file`), never `git clang-format`. Recompute by looping over files common to both trees and comparing `git show origin/main:f | grep -c $'\r$'` with the same on `origin/2.0.x:f`.
- **Nothing was renamed or deleted.** `git diff --find-renames --name-status origin/main origin/2.0.x -- src` is 45 A, 241 M, 0 D/R. "Moved" code means the old file stays, slimmed or turned into a shim, and the new file sits alongside. A 1.x fix always finds its file on 2.0.x, but the code may no longer be in it (see the map).
- **amber-engine boundary is enforced** (since cd86c1b3d). The OBJECT library (`src/CMakeLists.txt` amber-engine block, plus `target_sources` in `src/core/CMakeLists.txt` and `src/engine/CMakeLists.txt`) no longer links `Qt6::Widgets`/`OpenGLWidgets`/`OpenGL`/`Svg`: `#include <QWidget>` (or any widget class) in engine code fails to compile, and `amber-test-headless-render` links the engine with no UI sources and no stubs, so a call into `ui/`, `panels/`, `dialogs/` or `global/global.h` fails to link. Gap: `<QtWidgets/QWidget>` still compiles (`/usr/include/qt6` is on the path); only the link catches it. A main fix that, in engine code, opens a `QMessageBox`/`QFileDialog`, touches a panel or `amber::Global`, or uses `QApplication` becomes, on 2.0.x:
  - message / question / file dialog → `amber::app_ctx->showMessage()` / `showQuestion(title, text, warning)` / `showOpenFileDialog()`; `showMessage` off the GUI thread is queued and returns at once;
  - project state (filename, modified, current sequence, history, recents, autorecovery, rendering state) → `amber::project_io`; the UI refresh hangs off ProjectIO's signals in `AmberGlobal`'s constructor;
  - `QApplication::instance()` / `qApp` → `QCoreApplication::instance()`;
  - folder/sequence icons are produced UI-side (`AppContext::mediaTypeIcon`), footage icons/throbber via `setMediaIcon` / `stopMediaThrobber`.
  A new `AppContext` virtual needs an implementation in `ui/appcontextimpl.cpp` and `core/headlessappcontext.cpp` (test stubs derive from the latter). Export setup is `prepare_export()` / `finish_export()` (`rendering/exportthread.cpp`); ExportDialog keeps only viewer/dialog state.
- **New source file:** engine-side goes into the amber-engine list (or `core/`/`engine/` subdir CMakeLists), UI-side into `UI_SOURCES`. Effects shaders go into `AMBER_EFFECTS` (main: `OLIVE_EFFECTS`).
- **Renames** main → 2.0.x:
  - CMake `OLIVE_{SOURCES,RESOURCES,EFFECTS,QM_FILES,TARGET,EXPORT_PRESETS,DEFINITIONS}` → `AMBER_*` (`OLIVE_SOURCES` split into `UI_SOURCES` + amber-engine); define `OLIVE_OCIO` → `AMBER_OCIO`; env `OLIVE_EFFECTS_PATH`/`OLIVE_LANG_PATH` → `AMBER_*`.
  - `OliveGlobal` → `AmberGlobal` (pointer still `amber::Global`), `OliveAction` → `AmberAction`, `kOliveDefault*` → `kAmberDefault*`, `LabelSlider::DisplayType` → `amber::DisplayType` (`core/displaytype.h`).
  - Globals `recent_projects` / `autorecovery_filename` → `amber::project_io->recentProjects()` / `autorecoveryFilename()`.
  - `kTrackMinHeight` 30 → 15; its paint uses split into `kClipTriangleSize` (7, was `kTrackMinHeight >> 2`) and `kWaveformMinClipHeight` (20). A main hunk comparing against `kTrackMinHeight` in paint code usually maps to one of these.
- **AppContext** exists on both branches; 2.0.x adds `showQuestion`, `showSaveFileDialog`, `showOpenFileDialog`, `clearViewerMedia`, `getMainWindow`, `clearGraphEditorIfRow` (`core/appcontext.h:41-46`). Direct `QMessageBox`/`QFileDialog` calls in `effect.cpp`, `internal/vsthost.cpp`, `transition.cpp` are gone on 2.0.x; a main fix adding one there becomes an `app_ctx->` call.
- **Rich Text shadow opacity id is `shadow_opacity`** (EFX-9). The old `shadowopacity` id never reached the renderer, so every pre-fix project stores 0 in it; the rename makes `load()` skip it and the field default 100 keeps the old full-strength shadow. Never bring `shadowopacity` back on `RichTextEffect` (Text and Subtitle keep that id, theirs always worked). Main still has the dead field: port the rename with the wiring, not the wiring alone.
- **Effect XML bools** take `default="1"`/`"0"`; `"true"` reads as false (`ParseBoolField()`, same parse on main).
- **Executable** is `amber-editor` on both. `docs/2.0-spec.md` is tracked on 2.0.x despite `docs/` being gitignored; the rest of `docs/` is local only.
- **PRs:** fetch with `git fetch origin pull/N/head:refs/remotes/pr/N`. Merge on main with `gh pr merge N --squash --subject "..." --body ""` (keeps the author, no trailers), then port to 2.0.x with `git cherry-pick` (author preserved). Never `-X theirs`/`-X ours`: it silently drops one side of every conflicting hunk.

## Tests

- 2.0.x (21): amber-tests, amber-engine-tests, amber-test-{path,audio,headers,srt,effects,projectio,shortcutfile,keyframes,undo-markers,clipboard,deletion-plan,loadthread,projectsaver,rhi-smoke,rendering,timeline-layout,recordingtap,effects-gpu,headless-render}. All but timeline-layout and recordingtap link amber-engine; none links QtWidgets. Run with `QT_QPA_PLATFORM=offscreen`; never launch amber-editor from a session (WAYLAND_DISPLAY wins over an Xvfb DISPLAY and opens on the user's desktop).
- CI: `.github/workflows/tests.yml` runs ctest on push and PR, two jobs: `ubuntu` (ubuntu-24.04, Qt 6.10.2 via cached aqtinstall, FFmpeg 6.1 from apt) and `arch` (container archlinux:latest, whatever Qt/FFmpeg is current: Qt 6.12 / FFmpeg 9 at the time of writing). Both set `QT_QPA_PLATFORM=offscreen` and `AMBER_TEST_REQUIRE_GPU=1` (`src/tests/test_gpu_required.h`, macro `AMBER_SKIP_NO_GPU`: a missing GL context fails the GPU tests instead of skipping them) and run ctest under `xvfb-run -a` (llvmpipe GL needs an X display; without xvfb the GPU tests fail by design). Red arch + green ubuntu = an upstream update broke us, not a commit.
- `amber-bench-render` is a benchmark, not a ctest: `amber-bench-render [--rhi gl|vulkan] [--frames N] [--scenario solid|fx5|stack4]` prints median/p95 ms per 1920x1080 frame (compose + readback). GL forces offscreen QPA; `--rhi vulkan` needs a real display (Qt's offscreen QPA can't create a Vulkan instance), headless use `xvfb-run`. Noise is about ±0.1 ms on the median at 100 frames; use 300+ frames to see sub-0.2 ms gains. RX 6900 XT baseline (100 frames, median ms): GL solid ~1.0, fx5 ~2.4, stack4 ~1.8; Vulkan solid 0.85, fx5 1.28, stack4 1.27.
- main (9): amber-tests, amber-engine-tests, amber-test-{path,audio,headers,srt,recordingtap,timeline-layout,shortcutfile}; each compiles its sources directly.
- Real coverage, so a green run isn't oversold: `rhi-smoke` and `rendering` only create an OpenGLES2 QRhi, a texture and a clear/readback; `projectio` tests ProjectIO state; `projectsaver` does LoadThread → save → load → save on a fixture and requires byte-identical output plus spot checks (Text reveal/animatein fields, keyframes, transition, markers, guide, nest, `open="1"`); `loadthread` loads hand-written `.ove` fixtures (folder, sequence, version-mismatch question, footage probe); `effects-gpu` (125 incl. init/cleanup) is the per-effect pixel net; `headless-render` loads a generated `.ove` (Y4M checkerboard + WAV), exports 10 frames mpeg4/aac through `prepare_export` + ExportThread and checks frame count (no extra frame past `end_frame`), the sequence frame rate, pixels and audio length, and `nestedAudioMatchesFlat` exports a nested sequence's audio (audio-only pcm_s16le) and compares it with the same clips unnested. `effects-gpu` also renders LUT (identity, invert, half strength) and Corner Pin (symmetric distort, passthrough, one moved corner), and Rich Text shadow opacity (half strength, plus a pre-fix project whose dead `shadowopacity` = 0 keeps a full shadow). `effects-gpu` keeps its shader cache in `~/.cache/amber-test-effects-gpu` (shared between concurrent runs); `t1_yuv_input.mp4` is a single 33 ms frame that `Footage::get_length_in_frames()` floors to 0, so it can't be a timeline clip.
- Build in a separate dir (`build20/` for 2.0.x) with `-j16`, then `ctest --test-dir build20`.
- **Export audio start race, fixed on both branches** (caught by `nestedAudioMatchesFlat`, which flaked ~17% before). ExportThread's audio read used to be released by the first audio cacher to finish (single-use wake object, `compose_audio` only waits for cachers to start, and the `audio_track_count == 0` wake in `compose_sequence()` ignores nests), so later clips lost their first encoder frame or replayed it 1 s later. Now `compose_audio()` returns how many audio cachers it triggered (nested included, via `params.audio_cachers_triggered`), `Cacher::CacheWorker` calls `SignalAudioFill()` after every audio pass, and the export waits on `WaitForAudioFills()` (5 s safety timeout, `rendering/audio.cpp`). Playback still uses the wake object, so the nested-count wake still lets nested playback start before its audio is mixed (left alone on purpose). Ported to main as ff545969e (see the ledger).
- **Save quirk:** `EffectField::GetValueAt()` caches the evaluated value in `persistent_data_` and `Effect::save` writes it as `value=` for keyframed fields, so saved bytes depend on the last evaluated time (harmless on load, noisy diffs).
